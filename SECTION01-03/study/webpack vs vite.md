웹팩 : 여러모듈을 하나의 파일 혹은 소수의 파일로 묶어주는 번들링이라는 과정을 통하여 네트워크 요청을 줄이고 성능을 최적화한다
코드 스플리팅, 트리쉐이킹, 자원최적화 등의 기능 제공
강력한 plugin 생태계

hmr(핫 모듈 교체) 지원
: 개발 중 변경된 모듈만 교체하여 빠른 피드백 제공

하지만 웹팩은 모든 파일을 전부 번들링해야한다는 특징 때문에 초기 빌드 속도가 느리고 설정이 복잡하다는 단점이 있다
또한 개발 중에 변경된 사항이 일부일지라도 전체를 다시 번들링해야 하므로 느린 개발 서버 속도를 초래할 수 있다

바이트 : 모듈을 번들링하지 않고, 네이티브 ES 모듈 기능을 활용하여 개발 서버에서 직접 파일을 제공한다
현대 브라우저들이 ES 모듈을 지원하기 때문에 가능한 접근법이다
필요한 모듈만 즉시 웹 브라우저에 제공하므로 빠른 초기 로드와 개발 서버 속도를 제공한다

웹팩은 레거시 브라우저 지원이 필요하거나 복잡한 빌드 설정이 필요한 대규모 프로젝트에 적합하다
반면 바이트는 빠른 개발 속도와 모든 브라우저 지원이 필요하지 않은 최신 프로젝트에 적합하다

개발 단계에서는 ESBuild 의존성 사전 번들링

프로덕션 빌드 단계에서는 rollup 을 사용하여 최적화된 번들링을 수행한다

swc : speedy web compiler
빠른 속도의 자바스크립트/타입스크립트 컴파일러
Rust로 작성되어 매우 빠른 성능을 제공
바이트는 swc를 사용하여 소스 코드를 빠르게 변환하고 최적화한다
